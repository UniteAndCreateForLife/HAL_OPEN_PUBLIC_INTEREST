# Community and Sponsorship Readiness Roadmap

This document tracks public evidence that the project is becoming useful to people beyond its original maintainer. It is not an application to any fiscal sponsor and it is not a claim of nonprofit status.

## Why this exists

HAL Open Local AI is intended to remain independently useful, open-source, and technically separable from private HAL SUPREME work. Before seeking a long-term fiscal sponsor, the project should demonstrate that there is a real community, real public assets, and a real reason for a legal/financial umbrella.

## Readiness signals

### Community
- [ ] At least two independent contributors have had meaningful code, documentation, testing, review, or issue-triage work accepted.
- [ ] The issue tracker contains newcomer-friendly tasks with clear acceptance criteria.
- [ ] Contribution instructions have been exercised by someone other than the original maintainer.
- [ ] Release or roadmap decisions include public rationale and visible review.

### Technical maturity
- [ ] First tagged public release is reproducible from the repository.
- [ ] Local-only routing, fail-closed remote behavior, and the audit ledger have deterministic regression tests.
- [ ] External reproducibility review has been completed and findings are recorded.
- [ ] Security/privacy boundaries and unresolved risks are documented for each release.

### Project assets and continuity
- [ ] The repository has a maintained inventory of project-owned code, documentation, domains, package names, and other public assets.
- [ ] Bus-factor and maintainer-continuity risks are documented.
- [ ] Governance explains how maintainers, reviewers, conflicts, and spending decisions are handled.

### Funding readiness
- [ ] A concrete public-interest expense exists that should be paid from project funds.
- [ ] A small public budget maps each proposed expense to the approved open-source scope.
- [ ] There is evidence of donor/sponsor interest or recurring support need.
- [ ] Funding language clearly distinguishes ordinary sponsorship from tax-deductible charitable donations.

## Early-stage support

GitHub Sponsors can be used by eligible open-source contributors to receive one-time or recurring sponsorships before a separate fiscal-sponsorship relationship is justified. A repository can surface supported funding links through a .github/FUNDING.yml file.

GitHub Sponsors is not itself a statement that payments are tax-deductible. If a future fiscal host is used, the project should document that relationship and the applicable tax/funding boundary separately.

## Re-evaluation checkpoint

Revisit formal fiscal-sponsorship outreach after the community, technical, asset, and funding signals above are materially demonstrated. The purpose of that checkpoint is to show actual project need and continuity, not to optimize for an application form.

## Public evidence

The following repository files should be kept current as evidence develops:

- CONTRIBUTING.md
- GOVERNANCE.md
- MILESTONES.md
- BUDGET.md
- CONTRIBUTIONS.md
- EVIDENCE.md
- RELEASE_READINESS.md

All claims should remain backed by dated public receipts, tests, reviews, or release records.
